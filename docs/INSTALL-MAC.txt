EDUP - NHOE 0.12.1-PREVIEW.7 - MAC / CROSSOVER DRAG-AND-DROP

The native four-motor companion requires macOS 11.3 or newer. Its universal
binary supports Apple silicon and Intel. A tester felt rumble in an Intel
bottle with the controller in XInput mode. Native four-motor playback and
ARM/FEX rumble still need hardware confirmation.

INSTALL
1. Close Elite and the Frontier launcher. In CrossOver, select Elite's bottle
   and use Open C: Drive. Find the folder containing EliteDangerous64.exe,
   normally Products/elite-dangerous-odyssey-64. Back up matching mod files.
2. Check for an existing dinput8.dll before copying. If it belongs to another
   mod or a chained installation, keep it in place and stop here. For a
   standalone install or upgrade from this Mac package, copy the five loose
   files and ed-macos-haptics.app from Copy-to-game beside EliteDangerous64.exe.
   Keep the app intact and retain your existing ed-onfoot-haptics.ini.
3. In the SAME bottle, open Wine Configuration (Control Panels), Libraries.
   Add/select dinput8, click Edit, choose Native then Builtin, and save.
   Record any previous override before changing it. An existing correct
   override does not need to be changed again.
4. Connect your controller in its default XInput mode. Choose an Output value
   from RECOMMENDED CONFIGURATION and set it under [Controller] in
   ed-onfoot-haptics.ini. Use the configuration beside EliteDangerous64.exe.
5. For Output=auto or Output=macos, open ed-macos-haptics.app in Finder once.
   The capability check allows up to three seconds for discovery and sends no
   vibration. If macOS blocks the ad hoc signed app, use System Settings >
   Privacy & Security > Open Anyway when offered, then open it again.
   If it reports zero controllers, choose Retry with the controller active.
6. Close the capability check and launch Elite normally. The native companion
   starts automatically when enabled and exits after the game stops responding.

Keep your working Steam Input, controller bindings and graphics setup.
No d3d11.dll, DXMT, DXVK or ED-UP changes are needed. Leave Wine's XInput
libraries in use. No additional XInput override or Linux wrapper is needed.
No Windows driver, Bluetooth scanner, input mapper or service is installed.

RECOMMENDED CONFIGURATION
Edit the existing [Controller] section. Add it if missing. Set one Output value
and fully restart Elite after each change.

  Intel/Rosetta bottle, or a setup that already works with auto
    Output=auto
    Start here for native four-motor output with GameInput and XInput available
    as fallbacks. This is the packaged default.

  Apple silicon ARM/FEX bottle, or GameInput fails during startup
    Output=macos
    Start here to try native four-motor output with two-motor XInput fallback.
    This mode skips GameInput. ARM/FEX game-side haptics are experimental.

  Two-motor compatibility test, or isolating native companion issues
    Output=xinput
    Use XInput vibration only. This skips GameInput and the native companion.
    In the ARM/FEX bottle, this tests the game's two-motor route on its own.

Keep the controller in XInput mode for all three settings. The Output setting
changes vibration only. In the reported DInput tests on both bottle engines,
Elite loaded the controller bindings while the buttons and sticks stayed
inactive with or without this mod. Switch the controller back to XInput before
testing vibration.

NATIVE FOUR-MOTOR OUTPUT
The native companion queries Apple's GameController framework. For automatic
selection, it requires exactly one visible native controller with an Xbox
profile, four advertised individual actuator locations, four working engines,
and a single gamepad at XInput index 0. Multiple controllers or virtual
duplicates keep native output unselected. A virtual XInput device can still
meet the single-device check while macOS exposes a different physical pad.

Channels map separately: low-frequency body to left handle, high-frequency
body to right handle, left trigger to left trigger, right trigger to right
trigger. The companion uses Core Haptics; it does not route triggers through
XInput or invent missing actuator capabilities. Bluetooth/USB support depends
on what macOS exposes. A mask of 15 means all four locations were advertised;
it does not by itself prove physical vibration.

The bridge does not read buttons, axes, poses or trigger pressure, change
bindings/player indices, or request controller input focus. Controller
connection notifications and metadata are used only for output selection.
It omits VR adapters, OpenXR registration and Linux HID/xpadneo code.

FALLBACK AND SAFETY
There is a brief quiet interval during provider changes. Frames expire,
requests are finite, and loss of the game heartbeat stops the companion.
Repeated playback errors back off and eventually disable native attempts
until a controller reconnect or game restart, preserving fallback usability.
No per-session gameplay timer limits haptics.

SETTINGS
The supplied ed-onfoot-haptics.ini starts with:
  [OnFoot]
  Enabled=1
  Strength=60
  [SCO]
  Enabled=1
  Strength=60
  [ShipCombat]
  Enabled=1
  Strength=60
  [Controller]
  Output=auto
Use RECOMMENDED CONFIGURATION to select the Output value for your bottle.
SCO feedback is enabled at 60%, including with a preserved older INI.
It uses the game's local Status.json in the bottle or Windows Saved Games
folder. Engagement shakes the main motors unevenly and settles over 2.5
seconds. Disengagement gives a smooth 2.5-second slowdown in supercruise.
To change it, edit or add [SCO] Enabled=0 or Strength=0 to 100 in the INI
and restart.

SHIP WEAPONS
The preview adds main-motor feedback for matched ship weapon cues. It uses
a sustained effect for beams, a pulse for each multicannon shot and
shorter or heavier pulses for other weapon families. Physical calibration
and the inferred variants still need gameplay verification.

New INI files enable ship feedback at 60%. If you kept an existing INI,
add this section and restart Elite:

  [ShipCombat]
  Enabled=1
  Strength=60

Set ShipCombat Enabled=0 to turn it off. For authored effects only, set
Enabled=0 under [OnFoot], [SCO] and [ShipCombat].
Quiet authored Motion samples can now reach the main motors below the old cutoff.
Walking contacts stay disabled; running/sprinting remain enabled where mapped.

DIAGNOSTICS
Opening the app manually shows the detected device, controller count, actuator
mask and engine readiness. During a normal game launch, check the newest
session in the bottle's Windows temporary directory:
  %TEMP%\EDRumbleRestoration\<session>\restoration-status.json
  %TEMP%\EDRumbleRestoration\<session>\macos-haptics-status.json
The host reports macos-corehaptics when native output is active, macos-handoff
during a transition, or gameinput/xinput during fallback.
macos_helper_polls > 0 confirms the companion connected to this game session.
startup_stage and the hook errors show where initialization stopped.
output_restore_error reports whether a game output slot still needs cleanup
after shutdown. The stopped proxy keeps forwarding calls if cleanup fails.
gameinput_attempted marks when startup reaches the GameInput load attempt.
For Output=macos or Output=xinput, expect gameinput_attempted=0. For
Output=xinput, the native companion status file is absent by design.

Native status codes: 0 = no current error (also check ready); 1 = no native controller;
2 = multiple controllers; 3 = sole controller is not Xbox;
4 = missing individual actuators; 5 = engine/playback failure.
failed_actuator uses 1/2 for handles and 3/4 for triggers. Engine errors and
stop reasons are included. API success and frame counts are submission
observations, not measurements of physical motors.

On ARM CrossOver, the verified game image can supply read/execute trampoline
space if MinHook cannot allocate nearby. minhook_fallback_slots counts the
slots in use. If the motor-sender hook still cannot allocate its trampoline,
the game can use the verified audio frame callback. A headroom_frame_slot
value of 1 records that fallback. A headroom value of 1 indicates that the cap
for both authored main-motor channels is active. Check output and
macos_helper_polls to see which route is active.
Authored trigger negotiation requires the regular hook path.
headroom_minhook_status records the original MinHook result.
headroom_frame_slot_rollback_error reports a callback or page protection
that could not be restored during startup rollback.

If you selected auto or macos and the native status file is missing, check
first-launch app approval and macos_launch_error in restoration-status.json.
If controls fail in XInput mode, compare one launch with dinput8 set to
Builtin (Wine) in the same bottle. This bypasses the mod. Restore Native then
Builtin afterward.

For feedback, share the two status files if available and name any missing
file. Include the selected Output value, Mac model and CPU, macOS and
CrossOver versions, bottle engine, controller model and connection, Steam
Input state, and the action tested.

UNINSTALL
Close Elite and the launcher, allow the companion to exit, then remove the
five supplied loose files and native app, except pre-existing configuration
you kept. Restore backed-up files and the previous dinput8 override (or remove
the new override if none existed). manifest.json lists supplied file hashes.
